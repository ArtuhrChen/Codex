## 1. 一句話定位

**21st 是「社群投稿的 shadcn 風格 React + Tailwind 元件註冊表」**：7,000 多個元件、800 多位作者、250 多個 library，
每個元件都有即時預覽、可複製 TSX、`npx shadcn add` 一鍵安裝，並透過 **MCP / CLI / REST API** 讓 AI agent 直接搜尋與安裝。
一個產品、兩個動作（**Find** 找元件、**Generate** 用 21st AI 生元件）、三個介面（**Web、MCP、CLI**）。

- 官方自我描述：「Crafted React components that fight AI slop」—— 強調人工打磨而非 AI 均值。
- 創辦人 Serafim Korablev、Sergey Bunas；曾被 a16z 文章提及。
- **名稱對照**（避免搞混）：
  - Magic MCP ＝ 現在的 **21st MCP**（`@21st-dev/magic` npm 套件仍可用，v0.2.0 起代理到 `https://21st.dev/api/mcp`）。
  - Magic Chat ＝ 現在的 **21st AI**（`/magic-chat`、`/magic` 會轉址到 `/ai`）。
  - 舊 Magic console 發的 API key **已全部重置**，要到 https://21st.dev/mcp 重新產生。
  - 「Magic UI」是 Dillion Verma 的獨立 library（託管在 21st），跟 Magic MCP 無關。

**免費能做什麼 vs 付費才有什麼：**

- 免費：Web 瀏覽與即時預覽全部內容、`search`（MCP/CLI/REST 的 metadata 搜尋）、`search_logo`、markdown twin 讀取、每日 2 次完整取碼。
- 付費（Builder）：**無限取碼**。這是對 Claude Code 工作流最關鍵的一道牆——免費每天只能讓 agent 把 2 個元件的原始碼拉進專案。
- 付費（+AI）：MCP `generate` / CLI `21st generate` 用 21st AI 從 prompt 生元件。**基本 Builder 不含 AI**；免費層呼叫 `generate` 會消耗每日額度或直接回 paywall（`ai_subscription_required`）。
- Credits 按實際模型用量計費（簡單請求便宜、複雜生成貴），月額度不結轉、加購包結轉。

### 3.2 MCP（給 Claude Code）

**官方方式一：CLI 產生設定**（https://21st.dev/mcp.md ，本機實測輸出）

```bash
npx @21st-dev/cli@latest init --client claude          # 只印出設定
npx @21st-dev/cli@latest init --client claude --write  # 直接合併寫入專案 .mcp.json
```

實測印出的 `.mcp.json` 內容：

```json
{
  "mcpServers": {
    "21st": {
      "type": "http",
      "url": "https://21st.dev/api/mcp",
      "headers": { "x-api-key": "${API_KEY_21ST}" }
    }
  }
}
```

**官方方式二：`claude mcp add`**（純 HTTP MCP，依 `claude mcp add --help` 的 header 寫法）

```bash
export API_KEY_21ST=21st_sk_xxxxxxxx     # 到 https://21st.dev/mcp 產生
claude mcp add --transport http 21st https://21st.dev/api/mcp \
  --header "x-api-key: $API_KEY_21ST" --scope user
```

**官方方式三：Claude Code plugin**（magic-mcp 倉庫 README）

```bash
claude plugin marketplace add 21st-dev/magic-mcp   # 然後 /plugin install 21st
export API_KEY_21ST=21st_sk_...
```

**認證備註**（https://21st.dev/auth.md ）：
- `https://21st.dev/api/mcp`（完整）與 `https://21st.dev/api/mcp/readonly`（唯讀）都接受 `x-api-key:` 或 `Authorization: Bearer 21st_sk_...`，也支援 OAuth 2.1（Clerk，Claude 等 MCP client 可從 401 自動跳 OAuth 登入）。
- 實測：未帶 key 呼叫 `tools/list` → 401 `Not authenticated - your API key is missing or was reset`。
- REST v1 只接受 `Authorization: Bearer`，`x-api-key` 會 401。

**核心 MCP 工具**（mcp.md 列的代表性清單；完整以 server `tools/list` 為準）：

| 工具 | 功能 | 計費 |
| --- | --- | --- |
| `search` | 搜元件/主題/模板，只回 metadata | 免費 |
| `get_component` | 依 id 取完整程式碼 | **計入每日 2 次 / Builder 無限** |
| `get_inspiration` | 依專案 Design Context（stack、tokens）重排名的搜尋 | 免費 |
| `search_logo` | 品牌 / UI SVG logo 搜尋（svgl） | 免費無限 |
| `generate` | 21st AI 從 prompt 生 UI，回傳 URL 不是 inline code | 需 AI 方案 |
| `get_usage` | 查 `aiGenerationEnabled` 與額度狀態 | 免費 |

舊工具名自動轉譯：`21st_magic_component_builder`→`generate`、`21st_magic_component_inspiration`→`get_inspiration`、`logo_search`→`search_logo`。

### 3.3 CLI（`npx @21st-dev/cli`，bin 名 `21st`）

```bash
npx @21st-dev/cli login                  # 瀏覽器登入，token 存 ~/.config/21st/auth.json
21st search "health bar" --type c --json # 搜尋（c | theme | template），--tag --author --sort
21st get 143                             # 印出元件程式碼 + demo（計入取碼額度）
21st add theorcdev/8bit-health-bar       # 安裝到 components/ui/（底層是 shadcn）
21st add <user>/<slug> --print           # 只印 shadcn 指令
21st theme <id>                          # 印主題 CSS（免費）
21st logo discord --json                 # SVG logo
21st usage                               # 查額度與 AI 是否啟用
21st init --client claude --write        # 寫 MCP 設定
21st install-skill                       # 把 21st 的 7 個 skills 裝到全域
```

- 實測：**未登入時 `21st search` 直接拒絕**（`Not signed in. Run 21st login or set TWENTYFIRST_TOKEN`），`21st logo` 也回 403。
  所謂「搜尋免費」是指**登入後**不計額度，不是匿名可用。
- CI 用 key：`--api-key` 或 env `TWENTYFIRST_TOKEN` / `API_KEY_21ST`。
- 任一公開元件也可用原生 shadcn 安裝：`npx shadcn@latest add "https://21st.dev/r/<user>/<slug>?api_key=$API_KEY_21ST"`。
  實測不帶 key 打 `/r/manuarora700/hero-section` → **403** `authentication_required`（只回元件名稱與描述）。

### 3.4 不用 API key 的「markdown twin」方法 —— 以及它的限制

規則（llms.txt）：**在支援的頁面 URL 後面加 `.md`**，或帶 `Accept: text/markdown` header，就拿到純 markdown：

| 頁面 | 範例 |
| --- | --- |
| 元件 | `https://21st.dev/@<author>/components/<slug>.md` |
| 分類/tag | `https://21st.dev/community/components/s/<tag>.md` |
| 作者 | `https://21st.dev/@<author>.md` |
| library | `https://21st.dev/@<owner>/library/<slug>.md` |
| 其他 | `/pricing.md`、`/mcp.md`、`/ai.md`、`/auth.md`、`/blog.md`、`/changelog.md`、`/llms.txt` |

```bash
curl -sS -L -A "Mozilla/5.0" https://21st.dev/@manuarora700/components/background-ripple-effect.md
```

實測回傳（完整內容見 `snippets/21st/manuarora700__background-ripple-effect.md`）：

```markdown
# Background Ripple Effect

> A Hero component where background cells once clicked, create a ripple effect

- Author: [Manu Arora](https://21st.dev/@manuarora700)
- Library: [Aceternity UI](https://21st.dev/@manuarora700/library/aceternity-ui)
- License: mit
- npm dependencies: framer-motion
- Live preview: https://21st.dev/@manuarora700/components/background-ripple-effect

## Install

npx shadcn@latest add "https://21st.dev/r/manuarora700/background-ripple-effect?api_key=$API_KEY_21ST"

Requires a 21st API key ... Free accounts get a limited number of installs per day ...
```

**重要結論：元件 .md twin 只有 metadata（標題、描述、作者、library、license、npm 依賴、安裝指令），不含 TSX 原始碼。**
所以「不用 key 直接 curl 拿程式碼」在 21st 上**不成立**；真正能免 key 拿到的是：

1. **目錄層資訊**：tag 頁（每頁列 60 個元件 + 作者）、library 頁（完整元件清單）、author 頁（library 清單與數量）——這些對「發現」很好用。
2. **分類統計**：每個 tag .md 的描述行會寫出數量（如「284 hero components」）。
3. 若要程式碼：免費帳號每日 2 次 `get_component` / install，或直接去原始 library 的官網（Aceternity、Magic UI、Motion Primitives、8bitcn 都是開源 MIT，官網/GitHub 可免費拿完整碼）。

`.md` 不支援的頁：`/community/components/popular.md`、`/newest.md` 等「highlights」列表 → 404（實測）。listing 頁（`/community/templates`）也只有 HTML。

| 端點 | 狀態 | 回什麼 |
| --- | --- | --- |
| https://21st.dev/.well-known/api-catalog | 200, `application/linkset+json` (RFC 9727) | 兩個 anchor：`/api/v1`（service-desc → `/openapi.json`；service-doc → help.21st.dev、llms.txt；status → `/api/v1/status`）與 `/api/mcp`（service-doc → `/mcp.md`） |
| https://21st.dev/.well-known/ard.json | 200, JSON (ARD specVersion 1.0) | host `did:web:21st.dev`；6 個 entries：mcp.md、openapi.json、api-catalog、llms.txt、**skills/index.json**、auth.md，每項附 `representativeQueries`（agent 可用來比對意圖） |
| https://21st.dev/.well-known/skills/index.json | 200, JSON | **7 個 agent skills**（見下） |
| https://21st.dev/openapi.json | 200, OpenAPI 3.0, 45KB | 「21st API 1.0.0」，server `https://21st.dev/api/v1`，單一 `ApiKeyAuth`，**全部 endpoint 都要 key** |
| `/.well-known/openapi.json` | **404** | 注意：spec 不在 .well-known 下，而在根目錄 `/openapi.json`（api-catalog 與首頁 `Link` header 都指向這裡） |
| https://21st.dev/.well-known/oauth-protected-resource | 200 | RFC 9728；authorization server = `https://clerk.21st.dev`；scopes openid/profile/email |
| https://21st.dev/api/v1/status | 200 | 服務狀態 JSON |

### 4.1 skills/index.json 內容（對 Arthur 做 skill 最重要）

已存檔：`snippets/21st/skills-index.json`，7 份 SKILL.md 全文在 `snippets/21st/skills/`。

| skill | 一句話 | 大小 |
| --- | --- | --- |
| `21st-cli-use` | 用 `21st` CLI 搜尋/安裝/取碼；**有 `components.json` 的專案自動啟用，「先搜 21st 再手寫 UI」** | 5.0KB |
| `21st-ai` | 終端機用 21st AI：`21st generate` → `generation` → `iterate` → `take` 拉碼 | 5.4KB |

| `21st-ui-build` | 用專案自己的 design context（`.21st/design.json`、`.21st/DESIGN.md`）＋ 21st 搜尋結果做 production UI | 3.0KB |
| `21st-ui-explore` | 視覺方向未定時，探索多個明顯不同的 UI 方向 | 2.7KB |
| `21st-ui-review` | 依 design context、a11y、RWD、互動品質審查 UI，只套安全的機械式修正 | 2.2KB |

值得借鏡的寫法（可套到 Arthur 自己的 skill）：

- frontmatter `description` 直接列**觸發語句**（含多語言：英文 + 俄文），並寫明「Auto-activate when a project has a `components.json`」—— 用專案檔案存在與否當觸發條件。
- `21st-ui-build` 的流程：1) 讀 `.21st/design.json`；2) 檢查目標 route 與既有元件；3) **先搜再生成**；4) 重用專案 primitives；5) 檢查 `get_usage.aiGenerationEnabled` 才呼叫 generate；6) 保留 RWD/鍵盤/focus/reduced-motion/loading/empty/error 狀態；7) 跑 `21st review`。
- 「Design rules」段落明確列反模式：避免裝飾性漸層、過多卡片、玻璃效果、巨型標題、無意義動畫 —— 正好是 21st 社群元件最常見的「AI slop」風格，官方自己也在 skill 裡叫 agent 收斂。
- 每個 skill 結尾有「Handoff」：回報用了哪個方向、重用了哪些元件、改了哪些檔、做了什麼驗證，並把決策寫回 `.21st/design.json` 的 `decisions`。

### 4.2 REST API 端點概覽（openapi.json）

- 讀取：`GET /me`（身分/方案/額度）、`GET /components/search`、`GET /components/install/{username}/{slug}`、`GET /libraries`、`GET /component-workspaces`。
- 發佈：`POST /components/publish`、`/templates/publish`、`/themes/publish`、drafts 流程（`POST /components/drafts` 會開 sandbox → `/source` 推碼 → `/review` 產生封面/影片 → `/publish`）。
- 實測 `GET /api/v1/components/search?q=hero` 無 key → 401 `Missing or invalid Authorization header. Use: Authorization: Bearer <API_KEY>`。

## 7. 什麼時候用 21st 搜尋，什麼時候直接用 React Bits / Aceternity / MagicUI

影片評價「內容跟 React Bits 和前面介紹的重疊，品質參差」—— 實測屬實：Aceternity、Magic UI、Motion Primitives 在 21st 上都只是**鏡像**，而且 21st 鏡像拿碼還要 API key / 每日 2 次限制，原官網則免費完整。

### 7.1 判斷準則

**直接去原始庫（React Bits / Aceternity / MagicUI / Motion Primitives）當：**
- 你已知道要的效果屬於哪個庫（Aurora Background、Confetti、Sparkles、Text Effect）。原站免 key、文件完整、有 props 說明與 CLI。
- 需要完整原始碼餵給 Claude Code —— 21st 的 .md twin 沒有程式碼。
- 需要 MIT 授權確定性：21st 鏡像有不少 `License: unknown`（連 Aceternity Hero Section 都標 unknown），原站明確 MIT。

**用 21st 搜尋比較好當：**
1. **你描述的是「用途」而非「效果名」**：如「8-bit 血條」「HUD 瞄準框」「暫停選單」「成就 toast」「排行榜」—— 這些在 React Bits/MagicUI 根本沒有，21st 有 8bitcn、The Gridcn 等長尾社群庫，tag 搜尋（game-ui、hud）一次看全。
2. **需要「整段 section」而非「單一特效」**：hero 284 個、pricing 49 個、testimonials 42 個、login 25 個 —— 21st 是全網最大的 shadcn section 集散地，React Bits 完全不做 section。
3. **要跨庫比較同一類元件**：tag 頁把 Aceternity、Kokonut、Ruixen、個人投稿的「3D card」並排，比逐站翻快。
4. **用 MCP 讓 agent 自己找**：Claude Code 在專案裡遇到「需要一個 X」時，`search`（免費）給 metadata + demo 連結，再決定要不要花一次取碼額度。這是 React Bits 沒有的自動化流程（MagicUI 有 MCP 但只限自家）。
5. **找主題 / shader 背景 / icon**：803 個 theme、307 個 shader、icon 以語意搜尋 —— 其他三家沒有這些類別。
6. **找 template 整站骨架**（211 個）。

### 7.2 搜尋技巧

- **關鍵字用「用途 + 風格」**：`8bit health bar`、`hud status`、`pixel button`、`retro game over`，比 `progress` 精準。tag 本身當關鍵字：`game-ui`、`hud`、`achievement`。
- **先看 tag 頁 .md**（免 key、一次 60 筆含作者）：`curl https://21st.dev/community/components/s/game-ui.md`，再挑幾個開 Live preview。
- **看作者**：同一 tag 下優先挑 library 作者（有 `Library:` 欄位），避開只有 1–2 個投稿、`License: unknown` 的個人作品。
- **看 demo 再決定**：Web 預覽是即時 sandbox，可以玩互動（click ripple、hover tilt）。品質參差主要在 RWD 與 dark mode，預覽時切一下視窗寬度與主題。
- **看 install / like 數**：Web 元件卡片顯示安裝數與愛心；`/community/components/popular` 與 `/week` 是按安裝排序。MCP `search` 結果也帶 usage 指標（CLI `--sort`）。
- **看 npm dependencies**：.md twin 的 `npm dependencies:` 列出 framer-motion / three / gsap 等；遊戲專案若已用 PixiJS/Phaser，避免再拖一個 three.js。
- **留意付費內容**：Cnippet、ShadcnSpace 有 Pro 項目；CLI `--free` 可過濾。
- **省額度策略**（免費帳號）：用 `search` + Web 預覽 + `.md` 確認依賴 → 只對真正要用的元件花 `get_component`；或改去該作者的 GitHub（.md 的 Author 頁常有 GitHub 連結）拿碼。
